# 08: 路由参数统一校验

**What to build:** 按 ID 操作的接口直接把路径参数当字符串用，绕过了项目已有的参数校验。传入非法 ID 时，字符串被送到数据库，PostgreSQL 抛出类型转换错误，最终以 500 返回——而正确答案是 400（参数非法）或 404（资源不存在）。这类 500 既污染错误监控，也让调用方无法区分"我传错了"和"服务坏了"。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 所有按 ID 操作的接口（查询、更新、删除）在收到非法 ID 时返回 400，并给出可读的中文提示
- [x] 格式合法但不存在的 ID 仍返回 404，与现状一致
- [x] 数据库不再收到非法 ID——错误在进入数据层之前就被拦住
- [x] 覆盖全部存在该问题的接口，不遗漏（`request.params as` 由 10 处降至 **0**）
- [x] 新增测试：至少覆盖一个删除接口与一个更新接口的非法 ID 场景
- [x] 全量测试与类型检查保持绿色（shared 2 / api 9 / web 2 个测试文件全通过，`typecheck` exit 0）

**实现说明：** 统一改用既有的路径参数契约，校验放在处理函数最前面，早于请求体解析与数据库访问。

**覆盖范围：** 共 9 处（通知 2、成果 2、企业实践 1、授课任务 2、待办 2）；授课任务的更新接口与申请审批接口此前已使用统一校验，故未改动。新增一个跨端点的契约测试文件，用表驱动方式对这 11 条路由逐一断言"非法 ID → 400"，并额外断言"格式合法但不存在 → 404"未被误判。先见 9 条失败（返回 500）再修实现。

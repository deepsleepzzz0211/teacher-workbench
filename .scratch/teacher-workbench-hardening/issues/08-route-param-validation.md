# 08: 路由参数统一校验

**What to build:** 按 ID 操作的接口直接把路径参数当字符串用，绕过了项目已有的参数校验。传入非法 ID 时，字符串被送到数据库，PostgreSQL 抛出类型转换错误，最终以 500 返回——而正确答案是 400（参数非法）或 404（资源不存在）。这类 500 既污染错误监控，也让调用方无法区分"我传错了"和"服务坏了"。

**Blocked by:** None（可立即开始）

**Status:** ready-for-agent

- [ ] 所有按 ID 操作的接口（查询、更新、删除）在收到非法 ID 时返回 400，并给出可读的中文提示
- [ ] 格式合法但不存在的 ID 仍返回 404，与现状一致
- [ ] 数据库不再收到非法 ID——错误在进入数据层之前就被拦住
- [ ] 覆盖全部存在该问题的接口，不遗漏（以当前实现中直接断言路径参数类型的位置为准，逐一改为统一校验）
- [ ] 新增测试：至少覆盖一个删除接口与一个更新接口的非法 ID 场景
- [ ] 全量测试与类型检查保持绿色

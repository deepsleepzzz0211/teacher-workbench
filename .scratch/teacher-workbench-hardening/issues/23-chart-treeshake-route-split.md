# 23: 图表按需引入与路由懒加载

**What to build:** 图表库是整包引入的，且所有页面在入口处一次性静态导入，于是连登录页都要先下载整个图表库——用户还没登录就为图表付了流量和解析时间。做成：图表按需引入（只打包用到的图表类型与组件），页面按路由懒加载；登录页与首屏不再包含图表代码。用构建体积的前后对比作为证据。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 图表库改为按需引入，只包含实际使用的图表类型与必要组件（柱状图、饼图 + 网格/提示/图例 + Canvas 渲染器）
- [x] 页面按路由懒加载，访问某页时才加载该页代码（十个页面各自成为独立分包）
- [x] 登录页不再加载图表相关代码（以真实网络请求证明，见下）
- [x] 首屏与登录页的传输体积相比改造前有明显下降，并给出前后数字
- [x] 六个使用图表的页面照常渲染，图表交互（提示、图例、自适应）无回归
- [x] 懒加载期间有加载态，不出现长时间空白
- [x] 全量测试与类型检查保持绿色（shared 83 / api 161 / web 33 条用例全通过，E2E **24/24**，`typecheck` exit 0）

## 体积前后对比（同一构建配置，仅此改动）

| 产物 | 改动前 | 改动后 | 变化 |
|---|---|---|---|
| 图表分包 | 1,127.64 kB（gzip 379.0） | **526.93 kB（gzip 180.0）** | **−53%** |
| 入口分包 | 300.47 kB（gzip 92.3） | 238.08 kB（gzip 76.7） | −21% |
| JS 合计 | 2,783.30 kB（gzip 896.0） | 2,190.35 kB（gzip 710.4） | −21% |

登录页现在**完全不请求**图表分包，即相比改造前少下载 **526.93 kB（gzip 179.98）**。

## 验证方式

**"登录页不加载图表代码"是以真实网络请求证明的，不是看产物清单推断的。** 新增 2 条端到端守卫（`e2e/tests/05-bundle.spec.ts`）：一条断言访问登录页时没有任何图表分包的脚本请求，另一条断言进入含图表的页面后该分包确实被请求——后者用来防止前者因"分包根本加载不到"而假通过。

**图表渲染是实际看过的**：重新采集截图并逐一确认——工作台的柱状图（坐标轴、刻度、标签俱全）与成果页的环形图 + 图例均正常渲染，说明按需注册没有漏掉任何用到的组件。

**加载态**：路由懒加载在外壳内部有局部加载指示，避免每次切页把整个界面清空；入口另有兜底加载态覆盖登录页等外壳之外的场景。

## 维护提示（重要）

`EChart` 现在只注册了柱状图与饼图。**新增其它图表类型（如折线图）时必须同步在 `EChart.tsx` 里注册**，否则图表会静默不渲染——这类问题单测与类型检查都发现不了。

## 过程记录（诚实记录）

分包守卫的初版写得有缺陷：监听器在"登录"之后才挂上，而登录后落在的首页本身就有图表，图表分包早已加载完毕，导致断言失败。单独运行该文件时因时序侥幸通过，跑全量才暴露。已改为在导航前挂监听。

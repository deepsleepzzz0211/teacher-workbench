# 03: 代码规范工具接入（基线化，不批量改文件）

**What to build:** 接入 ESLint 与 Prettier 并纳入 CI，作为后续所有改动的格式与规范基线。关键约束：存量违规先冻结成基线，不做全量格式化提交——否则后续每一个功能 diff 都会被成千上万行格式变更淹没，无法审阅。

**Blocked by:** 02 CI 质量门

**Status:** ready-for-agent

- [ ] ESLint 与 Prettier 配置就位，且与 TypeScript 严格模式协同（不产生与类型检查重复的规则）
- [ ] CI 中新增规范检查步骤
- [ ] 存量违规以基线方式冻结（忽略清单或等价机制），CI 从第一天起即为绿色
- [ ] 新增或修改的文件受规范约束（基线只覆盖既有文件）
- [ ] 提供一键格式化命令，供后续按需对单个文件或目录执行
- [ ] 记录一条已知取舍：全量格式化留待宽重构阶段顺带完成，不单独开大 diff

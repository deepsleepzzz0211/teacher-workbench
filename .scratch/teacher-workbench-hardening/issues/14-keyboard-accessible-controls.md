# 14: 键盘可操作的账户菜单与通知列表

**What to build:** 全站没有任何无障碍属性，其中两处已经构成键盘陷阱：右上角的账户菜单是一个挂了点击事件的普通容器，键盘无法聚焦、回车打不开，等于没法退出登录；通知列表的每一行同样是"整行可点"的普通容器，只能靠鼠标阅读通知。做成：这两处都能用 Tab 聚焦、用回车/空格触发，并有对屏幕阅读器可读的名称。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 账户菜单可通过键盘聚焦，回车或空格可展开，展开后可用键盘选择"退出登录"
- [x] 通知列表项可通过键盘逐条聚焦，回车可打开详情
- [x] 可聚焦元素有清晰的聚焦态样式（见下方说明）
- [x] 图标类交互元素有可读的文本名称，屏幕阅读器不只念出"按钮"
- [x] 鼠标操作体验与外观不变
- [x] 新增组件测试：断言这两处可被键盘聚焦并触发（`apps/web/src/components/a11y.test.tsx` 新增 4 条）
- [x] 全量测试与类型检查保持绿色（shared 83 / api 161 / web 33 条用例全通过，E2E **22/22**，`typecheck` exit 0）

**实现说明：** 把两处"可点击容器"换成真正的原生按钮，由此自带可聚焦语义、回车/空格激活、以及对屏幕阅读器可读的名称（名称取自按钮内的文本内容）。账户菜单还需补一处：下拉菜单默认只响应悬停，键盘激活不会展开，因此把触发方式改为"点击 + 悬停"——既让键盘可用，又保留原有鼠标体验。

**关于聚焦态（诚实记录）：** 未额外书写自定义聚焦样式，依赖原生按钮的默认焦点环。这一条**没有自动化断言**——jsdom 不做布局与绘制，断言"焦点环可见"在单测里没有意义，需人工或视觉回归确认。

**关于外观（诚实记录）：** 账户菜单由内联样式重置了浏览器的按钮默认外观（背景、边框、字体继承），视觉上与改动前一致；但这一条同样由构造保证，未做像素级回归。

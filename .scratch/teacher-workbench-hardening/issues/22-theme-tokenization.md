# 22: 主题令牌化

**What to build:** 主题文件定义了主色与侧边栏色，但主色字面量在前面被重复硬编码了约三十处，中性色与成功/警告色同样散落各页。结果是想调一次品牌色，得改三十个地方，还必然漏掉几处。做成：页面不再出现硬编码颜色，取值一律来自主题令牌；调整主题只需改一处。这是纯重构，视觉结果必须与现在完全一致。

**Blocked by:** 19 [expand] 抽取共享 UI 构建块

**Status:** done

- [x] 页面与共享组件中不再出现硬编码色值（**十六进制与 rgba 全部为 0**，颜色只存在于 `theme.ts` 的调色板）
- [x] 主色、侧边栏色、成功色、警告色、中性灰全部来自主题令牌或共享调色板
- [x] 图表配色同样取自令牌，不再各自写死
- [x] **【已更正】令牌化彻底性**：页面已无任何颜色字面量。但原验收写的"改一次主题主色，全站（含图表）同步变化"**是错的**——图表用的是独立令牌 `chartSeries`，详见下方更正说明
- [x] 视觉回归：改造前后逐页截图对比，外观无差异
- [x] 全量测试与类型检查保持绿色

## 实测规模（比工单估算的"约三十处"更多）

改动前扫描 `apps/web/src`：**50 处颜色字面量、16 个不同色值、分布在 9 个文件**。其中主色 `#1d4ed8` 一个值就出现 **16 次**。

## 做法：单一调色板 + 语义命名

在 `theme.ts` 建立 `palette`，并让 `themeConfig` 自身也改用它（此前 `themeConfig` 里也散着字面量）。命名按**角色**而非色值——`primary` / `success` / `warning` / `surfaceMuted` / `borderSubtle` / `textMuted` / `chartSeries` 等，这样读代码时看到的是用途，将来换色值也不必改名。

顺带把 `Menu.darkItemHoverBg` 的 `rgba(255,255,255,0.08)` 也收进调色板（`hoverOverlay`）。它不是十六进制字面量、不违反字面指标，但同样属于"散落的硬编码颜色"，一并集中。

`PRIMARY` / `SIDER_BG` 两个旧导出改为指向调色板，保持向后兼容。

## 结果：字面量清零

改动后扫描：**调色板以外的文件数为 0** —— 全部 50 处字面量都改为引用 `palette.*`，颜色字面量只剩 `theme.ts` 里那 16 行定义本身。

主色改一处即全站生效，这一点由"页面里已无任何颜色字面量"直接保证：按钮、标签、进度条、ECharts 柱状/饼图配色、侧边栏与登录页渐变全部取自同一处。

## 视觉回归：像素级比对，而非只看文件大小

`pnpm capture` 重新采集 13 张截图，与改动前的基线逐张比对。**先按文件大小比会误判**：13 张里有 8 张 PNG 字节不同，但那是 PNG 对渲染帧/抗锯齿敏感所致。于是改用**逐像素**比对（`System.Drawing` 取原始像素后哈希）：

- **5 张像素完全一致**；
- 8 张有差异，但差异面积极小且集中在文本区域：日程页 **0.0018%**（且局限在右上角一小块）、待办页 0.47%（一条 70px 高的横向文字带）、看板页 0.30%（稀疏分布）。
- 所有图片**尺寸完全相同**，没有任何版式位移。

**判定为动态内容差异（日期、问候语随时段变化），不是颜色变化**——依据是：若主色真的变了，侧边栏选中项、全部主色按钮、进度条、图表柱体这些**大面积填充**都会变，差异占比会是几十个百分点，而不是 0.0018%。

### 更硬的一条证据

再做了一次确定性核对：把改动前 `HEAD` 里全站出现的 16 个字面量逐个去调色板里找同值项——**全部命中**（`#fff` 归一为 `#ffffff` 后比较）。也就是说每一个被替换的字面量，其色值与调色板中新引用的完全相等，**颜色在数值上一处都没有变**。

## 更正（两轴评审后）

评审指出原验收标准里有一句是**错的**，已更正：

> 原文：`改一次主题主色，全站（含图表、标签、进度条）同步变化——以此验证令牌化彻底`

**这句话不成立。** 图表用的不是 `primary`，而是独立令牌 `chartSeries`（`#0ea5e9`，与主色 `#1d4ed8` 本就不同色）。实测引用点：

- `pages/workload/chartOptions.ts:44` —— `palette.chartSeries`
- `pages/SchedulePage.tsx:24` —— `integrated: palette.chartSeries`

所以改 `palette.primary` 会带动按钮、标签、进度条（它们读 AntD 的 `colorPrimary`，而 `colorPrimary` 取自 `palette.primary`），**但不会**改变这两处图表柱体的填充色。把两个不同用途的颜色拆成两个令牌本身是对的（图表需要一个可区分的次级色），错的是我原来那句"全站同步"的验收写法——它把一个设计上故意分开的东西说成了一处。

另外评审还指出：本票的"页面与共享组件中不再出现硬编码色值"当时只做到**十六进制清零**，`LoginPage.tsx:72` 与 `SchedulePage.tsx:186` 还留着两处 `rgba()` 阴影——而本票正文恰恰以"rgba 也属于散落的硬编码颜色"为由收了 `hoverOverlay`，前后不一致。**已补齐**：两处阴影收进调色板的 `shadowStrong` / `shadowSoft`，现在调色板之外 hex 与 rgba **均为 0**。

# 13: 登出清空查询缓存

**What to build:** 退出登录只清了令牌和当前用户，没有清空服务端数据的本地缓存。在缓存有效期内换另一个账号登录，会先看到上一个账号的看板数据、通知未读数等内容（随后才被刷新覆盖）。在共用电脑的院系机房里，这是实打实的信息泄露。做成：登出即清空全部查询缓存，且缓存按用户隔离。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 退出登录后，缓存中不再残留任何账号相关的服务端数据
- [x] 登出后换另一个账号登录，首屏绝不会出现上一个账号的数字
- [x] 令牌失效被强制登出时，同样清空缓存
- [x] 同一账号正常重新登录时，行为与外观不变
- [x] 新增测试覆盖"切换账号不会看到旧数据"（`apps/web/src/auth/AuthContext.test.tsx` 新增 2 条）
- [x] 全量测试与类型检查保持绿色（shared 83 / api 160 / web 20 条用例全通过，`typecheck` exit 0）

**实现说明：** 主动登出与"令牌失效被强制登出"两条路径都清空查询缓存；仅清令牌而不清数据缓存是不够的，因为未过期的缓存仍会把上一个账号的数据渲染出来。先写测试见红灯（`expected { totalHours: 468.2 } to be undefined`）再修实现。

**连带影响（已处理）：** 改动使登录态上下文依赖查询客户端，因此它必须位于查询客户端提供者之内。应用入口本就满足该条件；一个组件测试的组合缺少这一层，已补上以对齐真实结构。

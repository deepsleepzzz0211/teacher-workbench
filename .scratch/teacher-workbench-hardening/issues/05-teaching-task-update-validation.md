# 05: 授课任务更新校验节次与周次区间

**What to build:** 创建授课任务时会拒绝"结束节次早于开始节次""结束周早于开始周"，但更新接口丢掉了这两条校验。结果是先建一条合法任务、再编辑一次，就能把非法区间写进库，进而污染课表展示与周学时分布。更新接口必须与创建接口口径一致。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 通过更新接口提交"结束周早于开始周"时被拒绝
- [x] 仅改动其它字段（学时、地点、人数等）时正常通过
- [x] 校验基于"合并后的最终值"而非仅补丁字段——即只改开始节次、使原结束节次变得非法时，同样被拒绝
- [x] 新增回归测试覆盖以上四种情况（`apps/api/test/workload.test.ts` 新增 7 条）

**实现说明：** 不再逐字段校验，而是把"既有记录 + 本次补丁"合并成最终状态，再用**创建时的同一份契约**整体校验一次。这样创建与更新共用一套约束，且天然覆盖"只改一个字段使另一个字段变非法"的合并场景。先写测试见 5 条失败（`expected 200 to be 400`，且能复现 `endSection` 被写成 1 的数据损坏），再改实现转绿。

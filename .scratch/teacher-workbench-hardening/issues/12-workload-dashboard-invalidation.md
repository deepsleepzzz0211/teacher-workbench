# 12: 工作量变更后看板数据同步

**What to build:** 在"教学工作量"页新增、修改或删除授课任务与其它工作量之后，回到工作台首页，首页显示的折算学时与达成率仍是旧值——因为工作量页的写操作只刷新了自己页面的数据，没有刷新首页用的那份。用户会看到两个页面数字互相矛盾，且不知道哪个是对的。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 新增授课任务后回到首页，总折算学时与达成率反映最新值
- [x] 修改授课任务后同理
- [x] 删除授课任务后同理
- [x] 新增 / 删除其它工作量后同理
- [x] 失效范围与其它页面（成果、企业实践、待办、申请）保持一致的口径，不留特例
- [x] 新增端到端用例：改工作量 → 切回首页 → 断言数字已更新
- [x] 全量测试与类型检查保持绿色（E2E **22/22** 通过；shared 83 / api 160 / web 18 条用例全通过）

**实现说明：** 工作量页的写操作原先只失效自己的查询，现补上首页那份，与其它页面口径统一。删除 / 修改 / 其它工作量走的是同一个失效函数，因此一并修复。

**测试覆盖说明（诚实记录）：** 端到端用例只覆盖"新增授课任务"一条路径。其余路径共用同一个失效函数，未逐一另写用例——若日后有人把这行失效单独拆开，现有用例不会报警。

**过程发现（重要）：** 第一版用例用整页跳转回首页，结果**在没有修复的情况下也通过了**——因为整页刷新会重建查询客户端、清空缓存，等于绕过了失效逻辑。改为经侧边栏的客户端路由跳转后，才复现出红灯：`Expected: 67.2, Received: 0`。这条经验已记入端到端测试的写法约定。

## 过程中挖出的两个环境陷阱（都已修，且都不是测试文件自身的问题）

### 1. `setup.ts` 里原有的 `getComputedStyle` 覆写是无效的，且交互测试会因此卡死

`apps/web/src/test/setup.ts` 里原本写着：

```ts
Object.defineProperty(window, 'getComputedStyle', { value: window.getComputedStyle })
```

这是一次**自赋值**，什么都没改。真实问题是：jsdom 不实现带伪元素参数的 `getComputedStyle(elt, pseudoElt)`，而 rc-util（AntD 表格行与弹窗测量滚动条）会传 `'::-webkit-scrollbar'` 调用它，jsdom 直接抛 `Not implemented`。该错误从 layout effect 里抛出会打断 React 的提交，表现为**用例整整 5 秒超时**而不是断言失败——非常容易被误判成"测试写得慢"。

改成丢掉伪元素参数、只走 jsdom 已实现的那条路径后，失败立刻变成可读的断言错误。

### 2. AntD Select 的下拉项必须点内层节点才会真正选中

`fireEvent.mouseDown` 打开下拉后，点 `role="option"` 外层节点**不报错但也不提交选中值**——预览会一直停留在空状态，`findByRole('option')` 却能正常找到元素，极具迷惑性。必须点它内层的 `.ant-select-item-option-content` 节点。

另外两个实测校正：`COURSE_TYPE_LABELS.practice` 是「实训课」而非「实训」；班级字段的 label 是「授课班级」。

### 3. 新增用例在完整套件里失败、单独跑却通过

整页渲染（两张表格 + 图表）加弹窗内表单操作，单个用例约 8 秒，超过 Vitest 默认 5 秒。**由于我一直在命令行手动传 `--testTimeout`，这个差异直到跑完整套件才暴露。**

修法是按套件放宽（`describe(..., { timeout: 20_000 })`）而不是调全局默认值——全局放宽会掩盖其它真正卡死的用例。

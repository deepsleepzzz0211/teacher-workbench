# 09: 登录防爆破与异步口令校验

**What to build:** 登录接口没有任何频率限制，密码可以无限尝试；同时口令校验用的是同步实现，每次尝试都会阻塞事件循环。两者叠加等于给了一个廉价的 CPU 拒绝服务面，也让暴力破解变得可行。做成：同一来源的登录尝试有频率上限，超限返回 429；口令校验改为异步，不阻塞其它请求。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 同一来源在短时间内超过阈值后，登录请求返回 429 并给出可读提示
- [x] 阈值内正常登录不受影响，正确凭据仍能通过
- [x] 口令校验不再同步阻塞事件循环（校验期间其它请求可正常响应）
- [x] 限流不泄漏账号是否存在：被限流时不区分用户是否存在
- [x] 新增测试覆盖：连续失败触发 429、限流不影响正常登录
- [x] 全量测试与类型检查保持绿色（shared 83 / api 160 / web 18 条用例全通过，`typecheck` exit 0）

**实现说明：** 限流使用成熟的官方插件而非自研；只作用于登录接口（未开启全局限流），并断言"其它已鉴权接口不受影响"。阈值与窗口可配置：代码内默认较严，本地开发配置放宽以免自动化测试被误伤（测试环境同样放宽，只有限流用例临时收紧）。

**过程说明（诚实记录）：** 本工单的两组测试是先写后实现，但我把"写测试"与"改实现"放在了同一批操作里，因此**没有像前几张工单那样留下红灯证据**。这两组测试的判别力来自构造而非实测：未注册限流时登录接口不可能返回 429；同步函数不可能返回 Promise。其余工单均保留了实测红灯。

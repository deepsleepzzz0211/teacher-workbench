# 11: 应用级错误边界

**What to build:** 现在任何页面在渲染中抛错，整个应用会卸载成白屏——用户只看到一片空白，没有提示、无法返回、只能手动刷新，而且刷新后大概率复现。做成：任一页面崩溃时展示一个可恢复的错误页，说明发生了什么，并提供"返回工作台"的出口；应用外壳（侧边栏、顶栏）保持可用，用户能切换到其它正常页面继续工作。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 单个页面渲染抛错时，不再整站白屏
- [x] 错误页给出可读的中文说明与"返回工作台"操作
- [x] 侧边栏与顶栏仍然可用，用户可以导航到其它页面
- [x] 错误页展示的细节不泄漏内部实现信息（如堆栈），详细错误写入控制台
- [x] 未发生错误时行为与外观完全不变
- [x] 新增组件测试：用一个必定抛错的子组件验证错误页出现且导航可用（`apps/web/src/components/ErrorBoundary.test.tsx` 新增 5 条）
- [x] 全量测试与类型检查保持绿色（shared 83 / api 160 / web 25 条用例全通过，`typecheck` exit 0）

**实现说明：** 边界包在页面内容之外、应用外壳之内，因此崩溃只影响当前页面而不影响侧边栏与顶栏；边界以当前路由为键，切换路由即自动复位，"返回工作台"因此能真正把用户带回可用状态。界面上不渲染任何异常细节，只写入控制台。

**覆盖说明（诚实记录）：** 组件测试用真实的抛错子组件验证了"错误页出现 + 不泄漏细节 + 正常时不影响渲染 + 返回操作会通知上层"。但"侧边栏与顶栏仍可用"这一条来自边界的**放置位置**（在外壳内部），没有对应的自动化断言——若要自动验证需要渲染完整外壳与路由，成本较高，此处未做。

# 06: 审批的权限与状态正确性

**What to build:** 调课/请假审批目前只要角色是院系管理员就能改任意申请的状态，没有任何状态守卫。三个后果要一并修掉：已审批过的申请能被再次翻转；管理员能审批自己提交的申请；任一院系管理员能看和批其他院系的申请，与"院系管理员"的定位不符。

**Blocked by:** None（可立即开始）

**Status:** done

- [x] 只有"待审批"状态的申请可以被审批；对已通过或已驳回的申请再次审批被拒绝，并返回可读提示
- [x] 提交人不能审批自己提交的申请，且该限制在提交人恰好也是管理员时同样生效
- [x] 管理员的申请列表、待审批列表、首页待审批计数三处口径一致，都限定在本院系范围内
- [x] 管理员在非本院系申请上的审批请求被拒绝（按"不存在"处理，避免探测资源是否存在）
- [x] 新增集成测试覆盖：重复审批、自审、跨院系三条路径（`apps/api/test/application.test.ts` 新增 7 条）
- [x] 全量测试与类型检查保持绿色（shared 2 / api 8 / web 2 个测试文件全通过，`typecheck` exit 0）

**实现说明：** 拒绝越权时返回"申请不存在"而非 403，沿用项目既有约定（不让状态码泄漏资源是否存在）。院系范围取自申请人所属院系与当前管理员所属院系的比对；管理员院系从数据库实时读取，不依赖令牌内容。

**测试数据说明：** 种子数据只有一个院系，无法验证跨院系隔离，因此本工单的测试自行建了一个其他院系的教师与其待审批申请，并在用完后清理（该教师删除时其申请随级联一并删除）。

**顺带修正：** 该接口原先直接断言路径参数类型，现已改用统一参数校验（其余同类位置由工单 08 一次性处理）。

# 16: 后端可发布产物

**What to build:** 后端没有任何编译产物——所谓的构建命令只做类型检查，运行始终依赖开发期的 TypeScript 运行时和完整源码目录。这意味着"构建通过"并不代表得到一个能部署的东西，生产环境也要带着开发依赖和源码。做成：构建产出一个可用 `node` 直接启动的后端产物，不含开发依赖，CI 验证它能起来并通过健康检查。

**Blocked by:** 02 CI 质量门

**Status:** ready-for-agent

- [ ] 构建命令输出可运行的后端产物（JS 形式，而非仅类型检查）
- [ ] 该产物可用 `node` 直接启动，不需要 TypeScript 运行时
- [ ] 不经构建即可启动的开发方式仍然可用（本地开发体验不变）
- [ ] CI 中新增一步：构建产物后实际启动它，并断言健康检查返回正常
- [ ] 共享契约包在产物模式下能被正确解析（不再是直接引用源码）
- [ ] 文档中关于构建与启动的描述与实际行为一致
- [ ] 全量测试与类型检查保持绿色

# 高职院校教师工作台

> 面向高职（专科层次职业院校）**专任教师个人**的一体化工作台。
> 把「课表 — 教学工作量 — 教科研成果 — 企业实践 — 调课请假 — 通知待办」收敛到一个界面，
> **数据一次录入、自动折算、实时汇总**。

前后端分离：React 19 + Ant Design 5 / Fastify 5 + PostgreSQL 15。开发过程遵循 TDD，关键路径具备端到端测试。

> **注意：这是演示项目，不是可以直接照抄上线的模板。**
> 仓库内的**数据库口令、演示账号口令、JWT 开发默认值都是公开的固定值**——它们的存在是为了让克隆后开箱即用、自动化测试可复现。
> 部署到任何他人可访问的环境之前，请务必：更换数据库口令、改掉或删除演示账号、并配置一个独立的 `JWT_SECRET`。
> 生产环境若仍使用示例默认值，服务会**拒绝启动**（这是有意的保护，不是故障）。

## 一、这个项目解决什么问题

调研（职业教育政策文件、院校教师发展中心公开资料、工作量管理制度）后归纳出四个高频痛点：

| 痛点 | 具体表现 | 本项目的应对 |
|---|---|---|
| 重复填报 | 课表、课时、科研、培训散落在教务/科研/人事多个系统，同一份信息反复手填 | 一个工作台承载教师个人全部事务数据 |
| 工作量核算繁琐 | 理论课、理实一体课、实训课、顶岗实习指导折算系数不同，还涉及班级规模、重复课，手工算易错且难自证 | 录入即自动折算，**每条记录可展开查看系数与算式** |
| 材料散落 | 论文、课题、竞赛、专利、教材、培训证书散落本地，评职称前集中翻找 | 六类成果统一登记 + 分类统计 + 业绩分汇总 |
| "双师型"要求难跟踪 | 政策要求教师每 5 年赴企业集中实践累计 6 个月，个人无法直观看到还差多少 | 自动统计近 5 年累计天数并展示进度与差额 |

政策依据（摘录）：

- 教育部《职业教育"双师型"教师基本标准（试行）》推动各地开展"双师型"教师认定工作。
- 上海市教委《深化人才培养模式全过程改革推动上海高等职业教育全面适配产业发展的工作方案》（2026）：明确"推动教师每 5 年赴企业集中实践 6 个月"。
- 教育部等四部门《职业学校兼职教师管理办法》；国家级职业教育教师教学创新团队、名师名匠培养计划。
- 院校教师发展中心建设评估指标普遍包含"建立教师个人业务档案""建设资源平台""组织教学竞赛与培训"。

结论：教师端最刚性的诉求是 **一次录入、自动汇总、随时可导出的个人工作台**，而不是再增加一个审批系统。本项目的范围因此严格限定在"教师个人视角"，仅附带一个轻量的院系管理视角用于审批与发通知。

## 二、功能清单

| 模块 | 能力 |
|---|---|
| 认证 | 用户名 + 密码登录（scrypt 哈希）、JWT、`/me`、角色区分（`teacher` / `dept_admin`） |
| 工作台首页 | 今日课程（无课时自动回退到下一个教学日并标明）、本周课表、工作量达成率、成果统计、企业实践进度、待办、最新通知 |
| 我的课表 | 学期 + 周次切换，周一到周五课表网格，课程类型色标 |
| **教学工作量** | 授课任务增删改；**自动折算**（课程类型 × 班级规模 × 重复课系数）；其它工作量按规则折算；学期汇总、达成率、周学时分布、课程类型构成；每条记录展示完整算式 |
| 教科研成果 | 论文/课题/竞赛/专利/教材/培训六类登记，按类别、级别、时间筛选，分类统计与业绩分 |
| 企业实践 | 实践经历登记，自动累计近 5 年天数并与政策要求的 180 天对比 |
| 调课请假 | 教师发起申请，院系管理员审批（通过/驳回 + 审批意见），状态流转 |
| 通知公告 | 置顶优先、打开即标记已读、未读数统计，管理员可发布 |
| 待办事项 | 增删改、标记完成、逾期高亮 |

### 教学工作量折算规则

```
折算学时 = 总学时 × 课程类型系数 × 班级规模系数 × 重复课系数
```

| 因子 | 取值 |
|---|---|
| 课程类型系数 | 理论课 `1.0`；理实一体课 `1.1`；实训课 `1.2`；顶岗实习 `1.5` |
| 班级规模系数 | 人数 ≤ 40 → `1.0`；> 40 → `min(1.3, 1 + (人数 − 40) × 0.01)` |
| 重复课系数 | 同一学期同一教师同一课程第 1 次 `1.0`；第 2 次及以后 `0.9` |
| 学期基本工作量 | `240` 折算学时 |

其它工作量：顶岗实习指导 `1.0 学时/人·周`、毕业设计指导 `4 学时/人`、技能竞赛指导 `20 学时/项`、社会培训 `1.2 学时/学时`、教研活动 `2 学时/次`。

> 规则集中定义在 `packages/shared/src/constants.ts`，计算实现在 `packages/shared/src/domain/workload.ts`。
> **前后端共用同一份实现**，因此前端表单里的实时预览与后端入库结果永远一致。

## 三、快速开始

### 1. 前置条件

- Node.js ≥ 20（实测 v22.19）
- pnpm ≥ 9（实测 v10.30）
- PostgreSQL 15（实测 15.18）

### 2. 准备数据库

默认连接串：`postgres://tw_app:tw_app_pwd_2026@127.0.0.1:5432/teacher_workbench`

创建角色与库（用你的超级用户执行一次）：

```sql
CREATE ROLE tw_app LOGIN PASSWORD 'tw_app_pwd_2026' CREATEDB;
CREATE DATABASE teacher_workbench      OWNER tw_app ENCODING 'UTF8' TEMPLATE template0;
CREATE DATABASE teacher_workbench_test OWNER tw_app ENCODING 'UTF8' TEMPLATE template0;
```

### 3. 安装与初始化

```bash
pnpm install
cp .env.example .env      # Windows: Copy-Item .env.example .env
pnpm setup                # = install + db:migrate + db:seed
```

### 4. 启动

```bash
pnpm dev
```

- 前端：http://localhost:5173
- 后端：http://127.0.0.1:3000 （健康检查 `/health`）
- 前端通过 Vite 代理把 `/api` 转发到后端，开发期无需处理跨域。

合计 **301** 条自动化用例（277 条单元/集成/组件 + 24 条端到端），全部通过；`pnpm typecheck` 与 `pnpm build` 均无错误。

端到端测试跑在**生产构建**（`vite preview`）之上而不是 dev server：dev server 首次加载会触发依赖预构建重载，
造成偶发的连接中断；跑真实产物既消除了这类抖动，也更贴近上线形态。`pnpm e2e` 会自动完成构建、启动后端与前端、灌入演示数据。

推送与 PR 都会触发 CI，依次执行 `typecheck` → `test` → `build`，全部通过后才跑端到端测试；任一步失败即整体失败。

集成测试跑在独立的 `teacher_workbench_test` 库上，测试文件启动时会重建 `public` schema；
测试辅助模块带**安全阀**：若当前连接的不是 `*_test` 库会直接报错，防止误清开发数据。

> 端到端测试的 `globalSetup` 会**先应用迁移、再重置并重新灌入演示数据**（`pnpm db:migrate` + `pnpm db:seed`），
> 以保证断言不受此前手工操作影响，并让它在全新的数据库上也能自足运行。
> **如果你在本地改过演示数据，跑 `pnpm e2e` 会把它重置。**

## 七、设计要点

**契约放在 `packages/shared`。** 后端用它做请求校验，前端用它做表单校验与类型推导，领域计算函数两端共用。结果是"接口文档"不可能与实现漂移——它们本来就是同一份代码。

**纯函数与 I/O 分离。** `packages/shared/src/domain/workload.ts` 不依赖数据库与 HTTP，因此可以用最快的单元测试锁死规则；`apps/api/src/modules/*` 只负责编排（取数 → 调领域函数 → 写库 → 出参），由集成测试覆盖。

**迁移是可审计的 SQL。** `apps/api/drizzle/*.sql` 是纯 SQL 文件，由自研的极简迁移器按文件名顺序在事务中执行并记录到 `_migrations` 表。测试环境因此可以反复"清库后重放"。

**口令用 Node 内置 `scrypt`。** 不引入需要本地编译的依赖，`node:crypto` 的 `scryptSync` + `timingSafeEqual` 已足够。

**越权隔离按"记录归属"实现。** 所有个人数据查询都带 `teacherId` 条件，修改与删除先校验归属，不属于当前用户一律返回 404 而非 403，避免通过状态码探测资源是否存在。

## 九、已知边界

- 本系统只服务"教师个人"视角，不含排课算法、学生端、学籍、财务、招生。
- 学期基本工作量（240 折算学时）与各项折算系数是按通行口径设定的默认值，实际落地时需按学校制度调整 `packages/shared/src/constants.ts`。
- 通知、报表导出、附件上传未纳入本次范围。
- 未配置安全响应头（HSTS / CSP / X-Frame-Options 等），面向公网部署时应自行补上。
